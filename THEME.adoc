= tilegroxy UI ("Survey" theme)
:url-repo: https://github.com/Michad/tilegroxy

This UI is built with `npx gulp bundle` (see link:README.adoc[README]) and produces `build/ui-bundle.zip`.
This page describes what the theme expects from the playbook and the content.

== Playbook

[,yaml]
----
site:
  title: tilegroxy Docs
  start_page: operation::index.adoc
  keys:
    manual_order: operation, development, decisions
    footer_text: 'Copyright© Michael Davis and individual contributors to tilegroxy. Tilegroxy licensed under <a href="http://www.apache.org/licenses/">Apache License, Version 2.0</a>'
content:
  edit_url: '{web_url}/edit/main/{path}'
  sources:
  - url: .
    branches: HEAD
    start_path: docs/operation
  # ...
ui:
  bundle:
    url: ./ui-bundle.zip
    snapshot: true
antora:
  extensions:
  - '@antora/lunr-extension'
asciidoc:
  extensions:
  - '@asciidoctor/tabs'
----

The header links (GitHub, Issues, Get tilegroxy) and the "Report an issue" link are derived from the content source's git remote when it's on GitHub or GitLab.
To override them, set `repo_url`, `issues_url`, `releases_url` and `product_name` under `site.keys`.
`manual_order` orders the manuals in the header by component name; without it, the start page's component comes first and the rest are sorted by title.
The footer falls back to `© <year> <site title>` when `footer_text` isn't set.
`site.keys.google_analytics` still enables Google Analytics.

NOTE: Antora camelCases `site.keys`, so templates read `site.keys.repoUrl` for `repo_url`.

"Edit this page" appears only when the page has a web edit URL.
A local source (`url: .`) gets a `file:` edit URL unless `edit_url` is set, and `edit_url: ~` turns it off.

The UI provides the `#search-input` field and the `search-scripts` partial hook the lunr extension expects.
The UI styles the output of the tabs extension and ships its script (`js/vendor/tabs.js`, from `@asciidoctor/tabs`), so the site doesn't need to supply either.

Don't override `head-styles.hbs` or `footer-scripts.hbs` with `supplemental_files`.
Doing so drops the fonts and the tabs script.
Remove any `table-filter.js`/`.css` supplemental files, since filtering is built into the UI.

== What the UI does automatically

* *Option tables become option rows.*
Any table whose first header is `Parameter`, `Option`, `Flag`, `Name` or `Key` and that also has a `Description` column (plus at least one of `Type`, `Required` or `Default`) is rebuilt as a list.
Each row gets an anchor (`#opt-url`).
A filter box appears at 6 or more rows.
Add the `nofilter` role to suppress the filter, or `nooptions` to keep a plain table.
* *Grouping.* Add a `Group` column to an options table and rows are grouped under headings, with chips to narrow by group.
The column itself isn't displayed.
* *Callouts beside code.* A listing (or code tabs) followed directly by a callout list is laid out side by side.
Clicking a number on either side highlights the line.
* *Code tabs.* Tabs that only contain code (YAML/JSON, Binary/Container) render as one dark card with a single copy button.
* *Code blocks* get a language label and a copy button.
Copied text excludes callout markers.
`\{placeholders}` are highlighted in YAML, JSON and shell blocks.
* *Admonitions* get a type label.
A block title becomes a heading.
* *On this page* is built from h2/h3 headings, with scroll-spy.
Use `:page-toclevels: 1` to show h2 only.
* kbd:[⌘ K], kbd:[Ctrl+K] or kbd:[/] focuses search.
The sidebar has a "Filter pages" box and expands only the current branch.

== Page attributes the header reads

[,asciidoc]
----
= Proxy
:description: The Proxy provider is the simplest option that simply forwards tile requests to another HTTP(s) endpoint.
:page-eyebrow: Provider
:page-config-name: proxy
:page-tags: ZXY · TMS · WMTS · WMS
----

[cols="1,3",options=header]
|===
|Attribute |Renders

|`:description:` |Lede under the title (also the meta description)
|`:page-eyebrow:` |Small label above the title (defaults to the parent nav entry, `none` hides it)
|`:page-config-name:` |Copyable `name: proxy` chip
|`:page-config-key:` |`key: layers[]` chip
|`:page-command:` |Copyable `$ tilegroxy seed` chip
|`:page-tags:` |Comma-separated plain chips
|`:page-pagination:` |Prev/next cards (set it in `antora.yml` to turn it on everywhere)
|===

----

== Home page

Set `:page-layout: home` on the component start page and make it the site start page (`site.start_page`).
The layout is styled by roles: `[.hero]` (containing `[.eyebrow]`, a `[discrete]` heading, `[.lead]`, `[.actions]` and an optional code block or code tabs), `[.paths]` and `[.features]`.
See `preview-src/home.adoc` for a complete example.

== Fonts

`head-styles.hbs` loads Source Serif 4, Source Sans 3 and Source Code Pro from Google Fonts.
To self-host, put the `.woff2` files in `src/font/`, add `@font-face` rules to `src/css/vars.css`, and remove the `<link>` lines.

== Content changes that complete the design

These need edits to the {url-repo}[tilegroxy] `.adoc` source:

* *Example before reference.* Move the `Example` tabs above the options table on provider, cache and auth pages.
* *Command flags.* Add a `Flag | Type | Default | Description` table to command pages so they render as option rows.
* *Diagrams.* Replace the draw.io PNGs with source diagrams via `asciidoctor-kroki` (D2 or Mermaid), using SVG output.
